# Changelog

## 2026-10-30

- **LLM providers (Sprint 22).** Responses whose `content` is a list of blocks (Mistral reasoning models such as `mistral-large-4`) are normalised: only text reaches the user (previously the stream broke). Request fields are chosen per provider and model (Mistral never receives fields it rejects; a rejected optional field is dropped and the request retried once). Per-slot **Reasoning** control (provider default / off / low / medium / high) mapped per provider replaces the global "Thinking / Reasoning" toggle (old "off" migrates to "off" on every slot). Temp / Max tokens / Context can be left blank (not sent). Each slot shows whether every control is sent, adjusted or ignored for the chosen model.
- **Prompt cache and usage.** The system prompt no longer embeds the per-turn retrieval: the turn-independent layers form a stable system prompt and the retrieved excerpts/tables are appended to the current message, so the whole prompt before the current turn can be cached by the provider. Context compression now reuses the same summary on every turn until the next threshold and only summarises new messages. Prompt, cached, completion and reasoning tokens are recorded per session and per slot; new **Usage and prompt cache** card. Anthropic gets cache breakpoints; optional per-connection provider options (per-session cache key hash, OpenRouter routing).
- Published images: `ghcr.io/dfergo/cbc-backend` (`arm64`) and `ghcr.io/dfergo/cbc-frontend` (`amd64`, `arm64`); tags `latest` (`main`) and `sha-<commit>`.
- Backend build arg `INSTALL_LOCAL_MODELS`: the published image ships without local embedding/reranker models (embeddings and reranking through an API); building from source keeps them by default. Clear errors in the log and the admin panel when no usable model is configured; the active mode is logged at startup.
- Frontend serves two surfaces on two ports: public (`80`) and backend-only (`8080`, `/backend/v1/*`). Backend requests are HMAC-signed (`CBC_BACKEND_SECRET` on the frontend, `CBC_FRONTEND_SECRET` installation secret on the backend).
- Frontend registration by address only, with per-frontend access modes (signed, trusted network, legacy), optional own secret and extra headers; **Security** panel and mode badges in Admin → Frontends. Existing registrations keep working unchanged (legacy).
- Deployment examples for LAN, VPS and same-host topologies (`deploy/`) and a new installation guide (`docs/INSTALL.md`).
- Searchable model field in the LLM and embedding slot editors (accepts an exact model ID).
